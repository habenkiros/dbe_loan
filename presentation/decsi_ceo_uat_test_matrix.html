2. How DECSI should run this test

Pilot shape (recommended)

  • 2–3 branches (one HO-adjacent, one typical branch)
  • 2 loan types DECSI actually books (e.g. MSME secured + one other)
  • 10–15 files through the factory (not 50 half-finished files)
  • At least 3 collateral shapes: building, land or movable, and Building + Land
  • At least 1 Digital Apply file if that channel is in this wave
  • At least 1 return-to-officer and 1 reject so those paths are proven

Who must sit in the room

  • Loan officer (creates and appraises)
  • Branch manager
  • Risk officer (Clear / Return)
  • Ops and Finance (pre-committee and disbursement queues)
  • Committee member at the level that would vote the amount
  • Field / engineer (GPS pack)
  • IT (access, backup, MFA)
  • UAT lead who owns this pack and the CEO page

Scoring rules — use these words only

ResultMeaningCEO impact
PassWorks as proposed. No workaround. Evidence noted (Queue ID / screenshot / time).Counts toward acceptance %.
PartialUsable, but missing a proposed control or needs a workaround. Log a Major or Minor defect.Does not block Go unless it is a Must-have domain.
FailCannot complete the step, or the control the proposal promised is absent (e.g. file reaches committee with no risk review when policy requires it).Must-have Fail = Hold or Go-with-conditions.
N/AOut of this wave on purpose (e.g. CBS auto-booking not connected; Market not in pilot).Does not lower the acceptance %. Write the reason.

Defect severity

SeverityWhen to useCEO rule
CriticalA real loan file cannot move, money could be booked wrong, or a policy gate can be skipped.No unconditional Go while any Critical is open.
MajorWorkaround exists (Excel, paper, second login) but audit / cycle-time / dual-control is weakened.Allowed on Go-with-conditions with owner and date.
MinorWording, layout, Amharic label, print layout — does not change the credit decision.Does not block Go.
Do not test the wrong thing. Loan type in this system is the DECSI credit product (working capital, housing, etc.). Appraisal is the shared 7-step MSME / corporate wizard — testers should not demand a different appraisal engine per loan-type name. Collateral screens follow collateral type (building / land / movable / mixed), not loan type. Collections and workout in the hub are the case file; CBS still posts cash.

3. Operating KPIs the CEO should see after the window

These are the proposal’s success measures (cycle time, completeness, returns). Measure on the same 10–15 pilot files. Write Excel/paper baseline if DECSI has it; otherwise write “no baseline” and still record hub times.

KPIHow to measureExcel / paper baselineHub resultBetter?
K1. Time to committee-ready pack Hours from Queue ID issued to first eligible committee submit (docs + appraisal + collateral + risk clear).
K2. Officer return rate % of those files sent back before first vote (incomplete, risk return, ops/finance return).
K3. Incomplete files stopped early Number of files blocked by document / DSCR / E&S / coverage / risk gate before committee time is used.
K4. Collateral pack at committee % of voted files that had GPS/photo (or recorded exception) and the correct building/land/movable totals.
K5. Closing to Finance queue Hours from committee approve to appearance on Finance disbursement queue (restriction, agreement, legal flags per policy).
K6. Digital Apply (if in wave) Register → upload → fee paid/waived → Queue ID → staff notification. Count successes / attempts. n/a
K7. Dual control Same person cannot vote their own file; MFA on for HO/committee roles; delegation used once without password sharing. — —

Target for a clean Go: K1 and K5 faster than paper; K2 down; K4 = 100% of voted files; K7 Pass; zero Critical defects.
