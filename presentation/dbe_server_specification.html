1. Purpose and deploy model

iBOC is the credit back-office for DBE: origination, KYC/documents, appraisal, GPS collateral, committees, seven financing product engines, and post-disbursement monitoring. It runs on-premises or in DBE private cloud. It is not multi-tenant SaaS. There is no vendor phone-home.

UAT / training

Configuration, UAT, and training-of-trainers. One VM is enough. Keep it off the production host.

Production

Live system for HQ and regional offices. Split application and database. Two app nodes preferred.

DR (recommended)

Cold standby or streaming replica. Restore drill at least twice a year.

If two app nodes each keep local disks, a file uploaded on node A is missing on node B. Shared media is mandatory for HA.

Firewall: staff and branches reach 443 only. PostgreSQL, Docker, and admin ports stay on the data-centre VLAN, jump host, or VPN. DNS: a name such as iboc.dbe.et (or DBE naming). Static IPs on all servers.

Workstations: current Chrome, Edge, or Firefox; 1920×1080 preferred for appraisal and collateral. Field GPS / camera requires HTTPS.

9. Security baseline (hosting)

  • TLS on every staff and tablet path; secure cookies; MFA (TOTP) for staff.
  • PostgreSQL not published to the internet; unique strong SECRET_KEY and database password per environment.
  • Disk / volume encryption for database and media; encrypted off-box backups.
  • Clock synchronized (NTP) — MFA codes fail if the server clock drifts.
  • Django Admin reachable only from jump host / VPN.
  • UAT and production use different secrets, license keys, and databases.
